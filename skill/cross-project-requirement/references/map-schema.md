# 工作区地图格式

只记录跨项目协作需要的长期事实。详细类说明、业务流程和编码规范留在各项目自己的文档中。

## 项目清单

`project-map.md` 使用下表：

| Project ID | 路径 | 主要职责 | 部署单元 | 拥有的数据 | 主要入口 | 状态 | 证据 |
|------------|------|----------|----------|------------|----------|------|------|
| `order-api` | `apps/order-api` | 创建和查询订单 | `order-api` 服务 | `orders` schema | HTTP `/orders` | `[已验证]` | `src/.../OrderController.java` |

规则：

- `Project ID` 在整个工作区唯一，优先采用部署或制品名称。
- “主要职责”写业务能力，不写“Java 项目”“公共模块”等技术描述。
- “拥有的数据”强调写入/生命周期所有权；只读取不等于拥有。
- 一行允许多个证据，但必须能定位到文件或符号。

## 项目详情

`projects/<project-id>.md` 使用以下结构：

```markdown
# <project-id>

- 路径：`<relative-path>`
- 职责：<一句话能力边界>
- 构建 / 启动：`<verified command or unknown>`
- 测试：`<verified command or unknown>`
- 证据更新时间：YYYY-MM-DD

## 模块

| Module ID | 职责 | 公开入口/导出 | 数据读写 | 状态 | 证据 |
|-----------|------|---------------|----------|------|------|
| `<project-id>:<module-id>` | ... | ... | ... | `[已验证]` | `path:line` 或 `path#symbol` |

## 对外契约

| Contract ID | 类型 | 提供方位置 | 消费方 | 兼容策略 | 证据 |
|-------------|------|------------|--------|----------|------|

## 外部依赖

| 目标 | 用途 | 调用位置 | 配置位置 | 状态 |
|------|------|----------|----------|------|
```

## 跨项目关系

`dependency-map.md` 分开记录两类边：

### 运行时调用

| Caller | Contract / Protocol | Callee | 用途 | 失败语义 | 状态 | 证据 |
|--------|---------------------|--------|------|----------|------|------|

### 静态或构建依赖

| Consumer | Package / Artifact | Producer | Version source | 状态 | 证据 |
|----------|--------------------|----------|----------------|------|------|

需要画图时，仅从表格中已验证的边生成 Mermaid 图；图是视图，表格才是可审计记录。

## 状态定义

- `[已验证]`：当前源码、配置、测试或权威文档直接证明。
- `[推断]`：多项迹象一致但缺少直接证据；写明待验证动作。
- `[未知]`：尚无足够信息；不得据此排除影响。

不要使用模糊的“应该”“大概”。将它们转换为 `[推断]` 加验证动作。
